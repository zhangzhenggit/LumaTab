# 上架操作清单

从零到提交的完整步骤。文案在 `STORE-LISTING.md`，隐私政策在 `PRIVACY.md`。

---

## 一、生成上架素材（一条命令）

```powershell
npm run store:assets
```

产物在 `dist/store-assets/`：

| 文件 | 用途 | 尺寸 |
| --- | --- | --- |
| `01-home.png` | 主截图 | 1280×800 |
| `02-folder.png` | 分组展开 | 1280×800 |
| `03-settings.png` | 设置面板 | 1280×800 |
| `04-gradient.png` | 纯色背景 | 1280×800 |
| `promo-440x280.png` | 小型宣传图块 | 440×280 |
| `promo-1400x560.png` | 顶部宣传图块（可选，但空着显得没做完） | 1400×560 |
| `store-icon-128.png` | 商店图标（**必填，且与 manifest 图标不是同一个资源**） | 128×128 |

截图与宣传图必须是 **24 位 PNG、无 alpha 通道**，带透明层的 RGBA 会被后台拒绝；
脚本产出的就是 24 位。商店图标相反，要的正是四周 16px 透明边——图片指南要求 128×128
画布里图形只占 96×96，而 manifest 里那个是满画布的（工具栏上正确，商店网格里偏大）。

脚本会临时加载真实构建、填入一批公开网站、截图，然后自己清理干净。

**必须在能上外网的机器上跑。** 图标要现场从各站点抓取；没有外网时会打印
`⚠ 一个真实图标都没取到`，截图里会是字母图标——依然可用，只是不如真实 logo 好看。
如果你的网络走代理，脚本会自动读取 Windows 注册表里的 PAC 地址并传给 Chrome。

想换截图里展示的网站，改脚本顶部的 `DEMO_SITES` 和 `DEMO_FOLDER`。

> 注意：脚本会临时把可选权限改成必需权限，只为了让无头 Chrome 能抓到图标——那正是
> 用户点过「允许」之后的真实状态。这份临时构建在 `.shot-build/`，跑完自动删除，
> **不会**进入上架包。

## 二、生成上架包

```powershell
npm run package
```

产出 `dist/lumatab-<版本>.zip`。打包脚本会拒绝把任何 `data/` 或 `imported-shortcuts`
文件打进去——个人书签不会外泄。上传的就是这个 zip。

## 三、用 GitHub Pages 托管隐私政策

后台要求填一个**公开可访问**的 URL。仓库已经是 `github.com/zhangzhenggit/LumaTab`，
用它的 Pages 最省事，全程免费、无需服务器。

### 3.1 先确认页面是最新的

```powershell
npm run privacy:page
```

这会把 `docs/PRIVACY.md` 渲染成 `docs/index.html`——GitHub Pages 实际提供的就是这个文件。

> 为什么不直接让 Pages 提供 `.md`：Jekyll 只处理带 YAML front matter 的 markdown，
> 裸的 `PRIVACY.md` 会被原样输出，浏览器里看到的是一堆 `#` 和 `|`，不适合交给审核员。
> **`index.html` 是生成产物，不要手改**；要改内容就改 `PRIVACY.md` 再跑一次这条命令。

### 3.2 推送到 GitHub

```powershell
git push origin main
```

### 3.3 开启 Pages

1. 打开 <https://github.com/zhangzhenggit/LumaTab/settings/pages>
2. **Source** 选 `Deploy from a branch`
3. **Branch** 选 `main`，右边的目录下拉选 **`/docs`**
4. 点 **Save**

等 1–2 分钟，页面顶部会出现绿色的 "Your site is live at ..."。地址是：

```
https://zhangzhenggit.github.io/LumaTab/
```

`docs/index.html` 作为目录首页，所以根地址直接就是隐私政策页，不用带文件名。

### 3.4 两个前提条件

- **仓库必须是公开的**（免费账号的 Pages 只支持公开仓库）。在
  Settings → General → 最下方 Danger Zone → `Change repository visibility` 改。
- 公开会连**全部提交历史**一起公开。已经核对过：`public/data/imported-shortcuts.json`
  从未被提交（一直在 `.gitignore` 里），全历史也搜不到内网地址；测试里原本用作示例的
  几个内部系统名也已经换成中性名称。

### 3.5 回填 URL

拿到地址后填到两个地方：

- `docs/STORE-LISTING.md` 详细说明末尾的 `<在这里填你托管后的 URL>`
- 开发者后台「隐私权规范」标签页的「隐私政策网址」字段

### 备选方案

不想公开仓库的话：把 `docs/index.html` 传到任何静态托管（Cloudflare Pages、Vercel、
Netlify 都有免费额度，也都支持私有仓库），拿到的 URL 一样能用。

## 四、在开发者后台提交

<https://chrome.google.com/webstore/devconsole>

1. **首次需要付 5 美元**一次性注册费（如果还没付过）。
2. 「新增项目」→ 上传 `dist/lumatab-<版本>.zip`。
3. **商品详情**标签页。注意后台的字段名和直觉不一致：
   - **软件包中的标题 / 摘要**：只读，自动读自 manifest 的 `name` 与 `description`，
     改不了，要改就改 `public/manifest.json` 再重新打包。
   - **说明**（16,000 字符）：这里要填的是**详细说明**，不是简短说明——简短的那句
     后台已经从 manifest 摘要里拿到了。把 `STORE-LISTING.md`「详细说明」整块粘进去。
   - **类别**：选「工具」。中文后台没有「生产工具」这一项。
   - **语言**：中文（中国）。
   - **商店图标**：必填，传 `store-icon-128.png`。
   - **屏幕截图**：传 4 张 `01`~`04`，上限 5 张。
   - **小型宣传图块**：`promo-440x280.png`。
   - **顶部宣传图块**：`promo-1400x560.png`（可选）。
   - **其他字段**里的「首页网址」和「支持信息页面网址」建议填上仓库与 Issues 地址，
     一个能点进去看源码的链接对"不收集数据"这类主张很有说服力。
4. **账号设置**（不在项目里，在整个开发者账号下）。点左上角汉堡菜单 →「设置」：
   - 填写**发布方联系邮箱**
   - 点验证，去邮箱收信完成**验证**

   这两步不做，「提请审核」会一直是灰的，而且报错信息里不会明说它在别的页面。

5. **隐私权规范**标签页（最容易被打回的一页，全部必填）：
   - **单一用途说明** → 抄 `STORE-LISTING.md`
   - **storage 权限的理由** → 抄
   - **favicon 权限的理由** → 抄
   - **主机权限的理由** → 抄（后台只有一个框，必需的 bing.com 和可选的全站权限
     写在同一段里）
   - **是否使用远程代码** → 选「否，我不使用远程代码」
   - 数据用途全部选**不收集**
   - 勾选底部**三条声明**（不出售、不作无关用途、不用于信用评估）
   - 填入隐私政策 URL：`https://zhangzhenggit.github.io/LumaTab/`

6. **分发**标签页：选择公开范围与国家/地区。
7. 「保存草稿」→「提请审核」。

> 「我为何无法提交？」那个链接会把还差的项一次列全，比自己逐页找快。列表里混着
> 项目内的字段和账号级设置，注意区分。

### Red Argon：1.0.0 被拒的原因与修正

后台原文：「对浏览器的新标签页和用户的搜索体验进行更改」，并给出纠正办法——
**如果新标签页包含搜索体验，则必须使用 Chrome Search API 来尊重用户所选的设置。**

问题不在于我们改了默认搜索引擎（`manifest.json` 里从来没有 `chrome_settings_overrides`），
而在于搜索框自己拼了一个固定引擎的查询地址。对审核而言这两件事是一回事：**覆盖新标签页
的扩展一旦自带搜索，就等于替用户选了引擎。** 页面上再小的搜索框也算。

三处一起改，缺一处都还可能被同一条打回：

| 改前 | 改后 |
| --- | --- |
| `SearchBar.jsx` 拼固定引擎的 `?q=` 地址 | `chrome.search.query({ text, disposition: "CURRENT_TAB" })`，并在 `permissions` 中加 `search` |
| 搜索框左侧画着某引擎的 logo | 换成中性放大镜；`public/assets/sites/` 整个删除 |
| manifest 描述写着「Google 搜索」 | 描述里不再出现任何引擎名 |

`tests/manifest.test.mjs` 里加了一条回归测试：在源码中搜索引擎域名 + 查询路径的组合，
命中即失败。**注释里也不能出现**——第一次改完就是被自己的注释绊住的，而审核同样是 grep。

真实验证过一次：无头 Chrome 加载构建产物，在搜索框输入文字回车，落地地址是
`https://www.google.com/search?q=…&sourceid=chrome&ie=UTF-8`。`sourceid=chrome` 是浏览器
自己拼的签名——说明地址由 Chrome 生成，不是我们生成的。把默认引擎换成百度就会走百度。

被拒后不能改这份草稿再交，**要提交一份新草稿**，所以版本号必须往上走（1.0.0 → 1.0.1）。

## 五、审核期间

- 涉及主机权限的扩展会走「深入审核」，比普通扩展慢，几天到两周都属正常。
- 被打回时后台会给出具体条款编号，改完重新提交即可，不用重新走一遍流程。
- 已经把全站访问做成了可选权限，这是审核里最常见的摩擦点。如果仍被问到，回答的依据
  在 `PRIVACY.md` 和「主机权限的理由」里，两处口径一致，不会自相矛盾。
- **如果在「分发」里选了延迟发布**：提交时的弹窗提到"通过审核 30 天后过期"——过审后
  必须在 30 天内手动点发布，否则这一版作废，要重新提交。选的是立即发布就没这回事。
- 审核期间不要动这个版本。要改就等结果：过审后再传新版本，被拒后按意见改。

## 六、发布新版本

### 版本号

改 `public/manifest.json` 和 `package.json`，**两处必须一致**（有测试盯着）。商店拒绝
它已经见过的版本号，所以漏改不是小疏忽——是排完队之后在最后一步被拒。

Chrome 接受 1～4 段点分整数，每段 0–65535，不能有前导零。

### 情况 A：上一版还在「待审核」

**审核期间无法上传新包，这是被禁止的，不是会替换。** 想传新代码只有一条路：

1. 商品详情页右上角 **⋮ → 取消审核**，退回草稿状态
2. 上传新 zip，重新提交

审核计时从头开始。所以这一步的取舍是：提交后不久发现要改，取消重提几乎不亏；已经排
了很久，那就等结果出来再更新。

### 情况 B：上一版已发布或被拒

直接上传新 zip 即可，商品详情不用重填。被拒的话后台会给出具体条款编号。

### 每次发版都要过一遍

- `npm test` 与 `npm run package`
- 如果改动会影响隐私描述，`PRIVACY.md` 必须同步更新，并重新跑 `npm run privacy:page`
  ——这一点已写进该文件的「政策变更」条款
- 商店截图与文案随时可改，且**不需要重新审核**，与版本发布无关
