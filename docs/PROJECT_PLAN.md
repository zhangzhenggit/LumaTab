# LumaTab 项目规划

## 产品目标

用一个快速、安静、可整理的页面替换 Chrome 新标签页：Bing 每日图提供每天变化的氛围，Google 搜索承担主要入口，快捷链接同时支持独立展示与文件夹收纳。

## 已锁定设计

- 视觉基准：第三版“紧凑层架”。
- 背景：Bing 中国区每日图，固定 13px 高斯模糊与蓝灰遮罩；无模糊度、图片源等用户设置。
- 搜索：620 × 54px 固定胶囊搜索框。
- 快捷项：桌面默认 64 × 64px，每行固定 16 个；内部品牌图标约 34px，使用矢量品牌资源或 128px favicon。窄屏按可用宽度减少列数。
- 图标：浅雾白实体底座。网站图标统一限制尺寸和留白；生成图标使用稳定哈希选择双色方案和名称前两字符。
- 布局：主页无分类标题和横线；普通链接与文件夹共同平铺，每行 16 个，所有项目显示名称。打开文件夹后使用独立的大号浅色圆角面板。

## 技术结构

```text
Chrome New Tab (React)
├─ SearchBar                 URL 识别 / Google 搜索
├─ ShortcutGrid             平铺、排序、悬停合并编排
│  ├─ ShortcutTile          独立链接
│  ├─ FolderTile            2×2 预览
│  └─ AddTile               新建快捷链接
├─ FolderPanel              大号浅色圆角文件夹面板
├─ Storage adapter          chrome.storage / localStorage 开发回退
└─ MV3 service worker
   └─ BingBackgroundService 接口请求、图片缓存、超时与回退
```

## 背景加载策略

1. 页面立即用内置雪山湖面 WebP 绘制首屏。
2. 如果 Cache Storage 中存在 Bing 图片，优先替换为缓存，避免等待网络。
3. 后台服务检查缓存是否超过 6 小时；需要时请求 `HPImageArchive.aspx`。
4. 仅接受 `https://www.bing.com/th` 图片、`image/*` 响应和 15MB 以内文件。
5. 请求使用 8 秒超时；更新失败继续使用旧缓存，没有旧缓存才保持内置背景。
6. 保存当天标题、版权说明和 Bing 搜索链接，页面可在右下角显示来源。

## 拖放规则

- 快速拖过或释放：调整项目在网格中的位置，并使用平滑位移动画。
- 在另一个链接或文件夹上悬停约 650ms，出现合并高亮后释放：新建文件夹或加入已有文件夹。
- WeTab 导入数据保留 `folder-icon` 分组及其子项顺序。

## 执行阶段

1. **基础工程（已完成）**：Product Design 原型模板、React/Vite、Manifest V3、扩展图标与构建脚本。
2. **背景服务（已完成）**：Bing 每日图、Cache Storage、元信息、本地回退、超时与输入校验。
3. **核心交互（已完成首版）**：搜索、16 列网格、添加、两种图标、平滑排序、悬停合并、文件夹面板与持久化。
4. **自动验证（已完成）**：URL/图标单测、生产构建、Sites 包装测试、扩展产物检查。
5. **Chrome 实机与视觉 QA（待连接 Chrome）**：加载 `dist/client`，验证新标签页覆盖、Bing 首次拉取、拖放和弹窗，并与第三版设计图同尺寸对照。

## 稳定性验收标准

- 新标签页不等待网络即可呈现完整背景和快捷链接。
- Bing 请求失败不白屏、不清空旧缓存、不影响搜索和快捷链接。
- 非 HTTP(S) URL 被拒绝，远端返回内容不进入 HTML。
- 数据变更写入 `chrome.storage.local`，重开标签页仍可恢复。
- 文件夹与独立项拖放后无丢项、重复项和嵌套文件夹。
- 1440 × 1024 与常见笔记本低高度视口不裁切搜索和三组快捷链接。
