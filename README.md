# LumaTab · 浮光新页

一个轻量、稳定的 Chrome 新标签页扩展。默认展示 Bing 中国区每日图片，提供固定 Google 搜索、自适应列数的快捷网格、拖放排序和文件夹。

界面按 WeTab 新标签页的实测尺寸 1:1 实现：60px 图标、16px 圆角、120px 网格单元、15/30 单元内边距、8px 标签间距、567×52 搜索框。详见 `AGENTS.md`。

## 当前能力

- Bing 每日图采用缓存优先加载，每 6 小时检查更新；断网或请求失败时使用上次缓存，再回退到内置雪山湖面壁纸。壁纸保持清晰，靠上下渐变遮罩和文字阴影保证白色标签可读，不做整屏模糊或压暗。
- 首屏渲染前先读本地壁纸缓存（250ms 预算），因此打开新标签页不会再先闪一下内置图再切换。
- 左下角齿轮打开设置，面板贴屏幕右侧、整屏高度、可上下滚动：预览近 7 天壁纸并固定其中一张、切回每日自动更新，或改用内置纯色渐变背景（12 组饱和的深宝石色 + 2 组浅色；靠明度差而非降饱和度让图标突出，选浅色时图标名称会自动转为深色）；同一面板可导出全部快捷方式为 JSON、从文件导入（导入前会让你选择「合并」或「替换全部」）。
- 「亮度」「模糊」都是作用在壁纸本身的 CSS 滤镜，而不是盖一层半透明遮罩——遮罩会让照片发灰、丢对比度，这也是早期版本调节效果差的原因。亮度以 50 为原图双向可调（0.45×～1.55×），提亮到一定程度后图标名称自动转为深色，避免白字看不清；模糊沿用 WeTab 的 `模糊/5` 比例（最大 20px），并把图层放大一点点让滤镜的虚边落到视口外。
- 照片壁纸会自动测量亮度并适度压暗（目标与深色纯色背景一致），让网站图标清晰凸显；只压暗不提亮，也不会压过头把照片压成黑块。一旦你手动拖过「亮度」滑杆，自动调节即永久停止，以你的设置为准。
- 打开设置时页面不会变暗，方便对照真实效果调节。
- 页面空白处右键为浏览器原生菜单；只有在图标上右键才是编辑菜单。
- 打开文件夹时面板出现在被点击图标的正下方（贴边时自动翻到上方），从图标位置放大展开，不会盖住图标本身；面板内图标与网格完全一致（同为 60px、16px 圆角、15/30 内边距）——WeTab 的文件夹面板同样不改变图标尺寸，打开文件夹更像是网格的一小块，而不是另一个尺寸的界面。文件夹磁贴上的 2×2 缩略图按 WeTab 实测的 7/20/6/20/7 布局，且每个小图铺满格子。
- 添加/编辑弹窗带实时磁贴预览，并可在保存前点「获取网站图标」直接抓取，抓到的图标会写入缓存，添加后不再发起请求。
- 固定尺寸搜索框，输入网址直接打开，其他内容使用 Google 搜索。
- 快捷区没有分类标题和层架横线；桌面按窗口宽度自动决定列数，图标尺寸不随宽度变化。
- 拖动时网格一格都不动：拖动开始时对网格拍一次快照，之后只拿指针和这份固定几何做判断，目标不会从光标底下滑走。落点由位置决定，没有任何计时器——压在图标上（含 10px 余量）就是合并，目标亮白环并张开；其余位置就是插入，缝隙里出现一根白色竖线。拖到现有文件夹即加入，拖到普通链接即新建文件夹；行的归属按图标中心判定，分界线落在两行图标的视觉中点。
- 分组面板内的图标拖出面板即移出分组；分组只剩一个图标时自动解散。
- 文件夹打开后使用居中的紧凑浅色圆角面板。
- 所有自动读取的快捷链接都使用完全相同的通用链路：读取站点根目录图标、页面声明的 `icon` / `shortcut icon` / `apple-touch-icon`，以及 Web App Manifest 图标，全部失败时才生成本地字母图标；不按网站名称或域名预置快捷图标。
- 取到的图标直接铺满整个磁贴、不加白底卡片，透明图标会直接压在壁纸上；分辨率不足以放大的图标落到浅色底上按固定比例居中显示——只要取到图标就一定会显示，字母图标只用于完全没取到的情况。未取到图标的站点使用纯色底 + 1~2 个白色字母，底色按域名哈希稳定选取。
- SVG 图标按结构校验通过（Chrome 的 `createImageBitmap` 无法解码 SVG，且 service worker 没有 DOM 可用于光栅化；此前所有 SVG 图标都会被静默丢弃）；只有 `viewBox` 没有宽高的 SVG 会自动补上固有尺寸。
- 只要磁贴当前显示为字母（无论是选了「字母图标」，还是「自动读取」没取到图标），就可以**直接点预览图上的文字修改**（最多 4 个字符，字号随字数自动缩放），底色色板紧贴在预览图下方方便对照切换；不改动则分别按名称和网址自动生成，不需要改名称。
- 图标一旦显示就不再变化：Chrome 本地图标库作为兜底在后台 service worker 内参与解析，结果直接写入缓存，页面不会先画低清占位图再替换。
- 自动图标与当前导入数据无关：每条用户链接独立解析、独立失败，图片必须通过解码、尺寸和可见像素校验，不使用 Chrome 通用地球占位。
- 图标解析顺序：站点声明的图标 → Apple Touch / SVG / Manifest 大图 → Chrome 官方 favicon 数据库兜底（适用于访问过的登录站点和内网页面）。整个过程都在 service worker 内完成，结果写入 Cache Storage 长期保存；失败结果缓存 10 分钟后自动重试，无需手动触发。
- Bing 背景维护最近 7 日图片：先缓存当前显示的一张，随后在后台预取其余几张，供设置页显示真实缩略图并支持离线切换。
- 网站图标请求沿用 Chrome 当前的系统代理、PAC 和内外网路由，不在扩展中另设代理。
- 数据保存在 `chrome.storage.local`；开发预览时自动改用 `localStorage`。
- 默认快捷区为空，不附带个人书签或演示链接；可以手动添加，也可以使用转换脚本导入自己的 WeTab 数据。

## 代码结构

```text
src/
  background/       Bing 每日图获取与缓存服务
  components/       搜索、快捷链接、文件夹与弹窗组件
  hooks/            快捷方式状态、壁纸、提示
  lib/              背景缓存键、图标解析、拖放判定、URL、持久化逻辑
  App.jsx            页面状态与拖放编排
  styles.css         固定设计令牌和响应式布局
public/
  assets/            内置回退壁纸、扩展图标、站点图标
  manifest.json      Chrome Manifest V3 配置
```

## 开发与构建

```powershell
npm install
npm run dev
npm test
npm run build:extension
npm run icons           # 重新生成扩展图标（16/32/48/128）
```

构建后的可加载扩展位于 `dist/client`。在 `chrome://extensions` 开启开发者模式，选择“加载已解压的扩展程序”，指向该目录。

## 权限说明

安装时只申请两项必需权限，浏览网站的权限是可选的、默认不申请。

- `storage`：保存快捷方式、分组结构和壁纸设置，全部存在本机。
- `favicon`：读取 Chrome 自己已经存有的网站图标，无需访问任何网站。
- `https://www.bing.com/*`（必需）：获取 Bing 每日图 JSON 与图片文件；这是唯一在安装时申请的站点权限。
- `http://*/*`、`https://*/*`（可选，默认未授权）：抓取各站点自己声明的高清图标，只做 GET，不修改任何网页。未授权时图标改用 `favicon` 提供的记录（通常 16/32px），功能不中断。可在设置面板的「网站图标」里随时授予或收回。
